Cleaning the WordPress database without breaking the site

The tables every page reads grow with revisions, expired transients, orphaned post meta and spam. Removing what is provably unused is safe; removing what a plugin still expects is how sites lose settings. HarrierCache limits itself to the first category and reports the byte count before it deletes anything.

Download plugin.zipWhat HarrierCache does

Safe: revisions beyond a keep-count

Every save stores a full copy. Keeping three to five per post is plenty for editorial work; the rest is history nobody opens. Deleting them does not touch the published post.

Take a copy first

Any cleanup should start with an export. HarrierCache can write a SQL dump of the affected tables to your uploads directory before deleting, so the state is recoverable without a full-site restore.

Careful: tables belonging to other plugins

Analytics, form entries, e-commerce orders and logs are not junk, even when they are large. HarrierCache does not touch a table it did not create; if a plugin's table is huge, that plugin owns the retention policy.

Safe: expired transients and orphaned meta

Transients have a lifetime and WordPress already expects them to vanish. Meta rows whose parent post no longer exists are read by nothing. Both are deleted without touching configuration.

Three numbers on the dashboard answer it: hit rate, bytes saved per request, and average generate time. A hit rate that climbs over a day of real traffic means the cache covers the pages people visit. Bytes saved moving means minification and image conversion are reaching the response. Generate time is what a visitor would have waited without the cache — if it does not drop, the pages are not being served from it.

Then confirm from outside: open the site in a private window, reload twice, and compare the server timing header before and after. A cached response is a few milliseconds of server work; an uncached one is your theme plus every active plugin. If the second reload is not markedly faster, an exclusion is swallowing the request.

Who this is for

Anyone who has installed a caching plugin, seen a green score, and still had a slow site. HarrierCache is aimed at the diagnosis as much as the fix: cache, output size, media and the database are counted separately, so the next thing to change is not a guess. It is not aimed at sites that need an edge network or a support contract.

What it does not do

No CDN. No image CDN. No edge computing, no page builder, no backup, no security firewall. HarrierCache does not rewrite your theme, does not inject a dashboard banner asking for a review, and does not phone home unless the administrator ticks the box on the dashboard. If a feature needs a remote service to work, it does not belong in a cache plugin.

Frequently asked

Will cleanup speed up my site?

It shortens queries on the tables it cleans. Expect a small but real gain, larger on old sites with tens of thousands of revisions.

Can I delete all revisions?

Yes, but keeping a few per post costs almost nothing and preserves editorial history.

Does it touch other plugins' tables?

No. Only rows and tables HarrierCache created or WordPress marked as disposable.
